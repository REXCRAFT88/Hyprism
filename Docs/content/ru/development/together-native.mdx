# Нативные компоненты Together

Функция Together для Windows поставляется с хостом ввода Hytale Together, средой SDL и менеджером контроллеров в `Sources/Hyprism.Desktop/Assets/Together`. Нативные бинарные файлы и соответствующая DLL SDL скопированы без изменений из Hytale Together 0.3.4. В исходном комплекте представлены соответствующее дерево исходников, файлы CMake и `Build.ps1` в каталоге `NativeSource`.

Исходный код взят из проекта `REXCRAFT88/Hytale-Together`. Адаптер распространяется по лицензии MIT. Для SDL и MinHook действуют собственные условия лицензий, приложенные к исходникам и бинарным файлам. Код интеграции Hyprism остаётся под GPL-3.0-only. При изменении и повторном распространении компонентов сохраняйте уведомления об авторских правах.

## Пересборка нативного хоста

Запустите `NativeSource/Build.ps1` в PowerShell на Windows с Visual Studio 2022 C++ Build Tools, CMake и локально установленным лицензированным клиентом Hytale. Передайте каталог, в котором расположен `HytaleClient.exe`. Скрипт извлечёт библиотеку импорта SDL из `SDL3.dll` клиента, соберёт нативные компоненты для x64 и оставит результаты в `NativeSource/build`. Файлы игры не копируются в лаунчер.

Проверьте полученные бинарные файлы и совместимость API SDL адаптера и лаунчера перед обновлением встроенных файлов. Интерфейсу требуется хост ввода `Assets/Together/HytaleInputHost.exe`, а SDL должна находиться рядом: `Assets/Together/SDL3.dll`.

## Проверка интеграции

Соберите решение с .NET 10 SDK из репозитория и запустите целевые тесты контекста профиля и аутентификатора. Регрессионный тест контекста должен загрузить аккаунт A, явно переключиться на B через асинхронное ожидание и убедиться, что обе сессии остаются связаны со своими идентификаторами профилей. В отчёте о выпуске отдельно указывайте результаты сборки и тестов и факт проверки на физических контроллерах и в авторизованной игре.
